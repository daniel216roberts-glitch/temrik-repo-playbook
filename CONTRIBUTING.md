# Contributing

Propose one operational improvement per issue or pull request. Describe the problem, affected step, proposed wording and a fictional acceptance scenario. Include contrary evidence or limitations where relevant. Do not upload live contracts, personal data, credentials or confidential project records.

Maintain the ten core sections: Trigger, Input, Checks, AI assistance, Exceptions, Human decision, Action, Evidence retained, Escalation and Output. Keep all standalone agent safeguards in each file. Changes to approval boundaries require explicit maintainer review.

Use source locators, explicit unknowns and testable outputs. Do not add universal legal deadlines, unsupported entitlement rules or promises of outcomes. Jurisdiction-specific additions need a current authoritative source, effective date, applicability limits and professional review.

Before proposing a change, run `python3 scripts/validate.py`. Also exercise changed scenarios in the target agent and report the exact model/tools/version, result and limitations. Do not claim that structural checks establish operational reliability.
