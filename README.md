# TEMRIK Repo Playbook

**Practical construction playbooks for teams and their AI agents.**

Built for teams that actually build.

Six detailed, standalone Markdown procedures for organising project information, checking evidence and preparing decisions. Download one file and load it into your approved agent environment. No TEMRIK account is required.

## Download a playbook

| Playbook | Use it when | Main output |
|---|---|---|
| [Contract Before Signature](playbooks/01-contract-before-signature.md) | A draft contract, subcontract, purchase order, amendment or proposed renewal is received; or the document set changes before signature. | CONTRACT ALIGNMENT REPORT plus OBLIGATION REGISTER and EXECUTION DECISION SHEET. |
| [Variation Control](playbooks/02-variation-control.md) | A possible change in scope, design, quantity, access, method or sequence is reported, or a revised instruction/drawing is received. | VARIATION CONTROL PACK: change statement, evidence index, notice checklist, valuation, time referral and approval log. |
| [Payment Evidence](playbooks/03-payment-evidence.md) | A payment claim is being prepared or received, a certificate is issued, or a payment discrepancy is identified. | PAYMENT EVIDENCE PACK: line-item schedule, evidence index, period reconciliation, cash ledger and exception list. |
| [Meeting Decisions and Actions](playbooks/04-meeting-decisions-actions.md) | An authorised meeting record, transcript, notes or action update is available for processing. | DECISION RECORD plus ACTION REGISTER and FORMAL-INSTRUCTION REFERRAL LIST. |
| [Delay and Early Warning](playbooks/05-delay-early-warning.md) | A late decision, changed sequence, access restriction, delayed procurement, weather event, resource issue or programme variance is reported; or a scheduled programme review occurs. | EARLY WARNING BRIEF plus EVENT CHRONOLOGY, PROGRAMME EVIDENCE GAPS and MITIGATION OPTIONS. |
| [Dispute Prevention](playbooks/06-dispute-prevention.md) | A repeated unresolved issue, disputed instruction, conflicting account, missed commitment, unpaid amount or explicit disagreement is identified during an authorised review. | DISPUTE PREVENTION BRIEF plus SHARED-FACTS REGISTER, RESOLUTION OPTIONS and IMPLEMENTATION LOG. |

On GitHub, open a file and use **Raw / Download raw file** to save it. To download everything, use **Code → Download ZIP**. Keep live project records in private, approved storage, never in this public repository.

## Start using it

1. Download the complete Markdown file. Each contains its own operating instructions and approval rules; no other file is required to understand the procedure.
2. Read it and configure jurisdiction, project role, reviewers, data permissions and output location.
3. Load it into the instructions/knowledge mechanism your agent supports. Ensure the entire file is available; retrieval of only a fragment may omit important controls.
4. Run the fictional example and acceptance scenarios before adding live information.
5. Provide only authorised project inputs. Ask the agent to use the start command at the end of the playbook.
6. Review source coverage, exceptions, calculations and draft outputs. Humans approve legal/commercial positions and external actions.

An agent with no filesystem can return the tables in chat. An agent with document access can read approved files. A connected agent needs tool permissions and approval enforcement configured in its host platform. Markdown alone cannot enforce security or cause background monitoring.

## What every file includes

Trigger, inputs, intake questions, evidence rules, detailed procedure, checks, AI assistance, exceptions, human decisions, actions, retained evidence, escalation, output templates, a fictional worked example and six acceptance scenarios. Instructions distinguish facts, interpretations, assumptions and proposals.

## Release status

**0.1.0 — public preview.** Editorial and structural checks are recorded in VALIDATION.md. Acceptance scenarios are supplied for testing in your chosen agent; they have not been executed across commercial agent platforms. These are general operational procedures, not legal, engineering, safety or financial advice. No promise is made that using a playbook prevents disputes or satisfies a particular contract.

The six playbooks are an initial practical collection supporting TEMRIK’s construction peace approach. They are not claimed to be a one-to-one map of all 27 ebook chapters. The ebook’s existing action boxes are not changed by this repository release.

## Improve the collection

See CONTRIBUTING.md. Use fictional or thoroughly de-identified examples. Do not put confidential contracts, names, active disputes, credentials or personal data in an issue or pull request. The repository is a resource, not an emergency or professional advice service.
